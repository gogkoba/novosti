# Новости — служба подготовки выпусков для канала в Max

Ежедневный цикл: сбор новостей → дайджест на проверку → речь ведущего → проверка → сохранение в git.
Редакционные правила — `RULES.md`. Маркировка иноагентов и запрещённых организаций — `LEGAL.md`. **Читай оба целиком перед любым шагом. Маркировка обязательна всегда, это требование редактора номер один.**
Эталоны формата — `examples/` (см. `examples/README.md`).
Как писать без признаков ИИ-текста — скилл `human-writing` (`.claude/skills/human-writing/SKILL.md`). **Загружать перед написанием любого текста: дайджеста, речи, статьи, правок.** Требование редактора от 12.09.2026.

## Структура

```
CLAUDE.md          — этот файл: как работать
RULES.md           — редакционные правила: отбор, тон, язык, форматы
LEGAL.md           — маркировка иноагентов / экстремистских / террористических / нежелательных, армия
examples/          — образцы выпусков за 04–08.09.2026
output/ГГГГ-ММ-ДД/ — рабочие файлы выпуска за день
  01_digest.md     — дайджест 15–20 новостей на проверку
  02_speech.md     — речь ведущего из одобренных новостей
  03_column.md     — авторская статья (по команде)
  rejected.md      — что нашли и не взяли, с причинами
```

## Команды (пользователь пишет одно слово — ты делаешь весь шаг без уточняющих вопросов)

| Команда | Что делать |
|---|---|
| `новости` / `дайджест` | Шаг 1. Собрать 15–20 новостей по `RULES.md` (окно 12:00 вчера — 12:00 сегодня ± 2 ч, плюс важное упущенное). Записать `output/<сегодня>/01_digest.md` и `rejected.md`. Показать пользователю список заголовков с номерами. |
| `убери N, M` / `в реджект N, M` | Убрать новости из дайджеста. «Убери» — просто удалить, «в реджект» — удалить и записать в `rejected.md` с причиной, которую назвал пользователь. После этого перенумеровать оставшиеся. |
| `на проверку` | Собрать из текущего дайджеста чистый файл `output/<сегодня>/Новости_<сегодня>.md`: та же нумерация и формат, но без тегов в квадратных скобках. В Downloads md-файл не класть (решение редактора от 16.09.2026): туда идёт только Word. |
| `ворд` | Собрать Word из того, что делали последним. Дайджест: `python tools/md2docx.py output/<сегодня>/Новости_<сегодня>.md` — с фото и кликабельными ссылками (если чистого файла нет — сначала `на проверку`). Речь: `python tools/speech2docx.py output/<сегодня>/02_speech.md` → `Речь_<сегодня>.docx`. Статья: тот же скрипт с `-t "Авторская статья"`. Копию Word всегда класть в `%USERPROFILE%\Downloads\`. В Downloads только docx, md-версии туда не копировать. |
| `речь` | Шаг 2. Взять все новости, которые остались в `01_digest.md` после команд «убери» / «в реджект», и собрать из них речь ведущего в `02_speech.md`. Галочек в дайджесте нет и вопросов «брать ли все» не задавать (решение редактора от 16.09.2026). Показать целиком. |
| `статья` | Авторская статья по самой важной одобренной новости (или по указанной) в `03_column.md`. Показать целиком. |
| `версия А` / `версия Б` / `Б, но …` | Ответ на выбор между черновиком и версией после `human-writing`. Сделать выбранную версию основной, собрать Word, записать выбор и замечания в `humanizer_log.md`. |
| `правки: ...` | Внести правки в последний созданный файл, показать только изменённые фрагменты. |
| `сохрани` | `git add -A`, коммит `Выпуск ГГГГ-ММ-ДД` (повторный — `Выпуск ГГГГ-ММ-ДД: правки`), `git push`. |

Дата — сегодняшняя по системным часам (Москва). Если папка `output/<сегодня>/` уже есть — дополняй, не затирай без просьбы.

## Бюджет сессии — правило редактора от 10.09.2026

Весь дневной цикл (новости → речь → ворд → сохрани) должен укладываться в один сессионный лимит. Лимит конечен, а токены, потраченные на незавершённую работу, пропадают. Поэтому:

- **Агенты (субагенты) — не больше двух за весь шаг, и только для сбора новостей.** Каждый агент тратит в 5–10 раз больше токенов, чем прямой поиск из основной сессии, и если лимит кончается посреди его работы, результат теряется целиком. 10.09.2026 восемь параллельных агентов сожгли весь лимит и не вернули ничего. Видео, фото, проверку по реестрам и правки делать самому, прямыми запросами WebSearch/WebFetch, без агентов.
- **Порядок в шаге 1 — сначала результат, потом украшения.** (1) Собрать новости и сразу записать `01_digest.md` с текстом, источниками и теми фото, что уже попались; в строке «Видео» временно «нет». (2) Сразу собрать чистый файл и Word (как по командам `на проверку` и `ворд`), Word положить в Downloads. (3) Только после этого искать видео и недостающие фото и дописывать их в файл, пересобирая Word в конце. Если лимит кончится на этапе 3, у редактора всё равно есть готовый дайджест.
- **Экономить запросы.** На видео — столько запросов, сколько нужно, чтобы найти 1–2 ролика к каждой новости (правило от 16.09.2026), но запросы группировать: один поиск по-русски и один по-английски на новость, все новости одной пачкой; ленты агентств читать одной страницей, а не по статье. Не перечитывать файлы, которые уже в контексте.
- **Контрольные точки каждые 20 минут (правило редактора от 10.09.2026).** В начале шага запомнить время старта. Через 20 минут работы, если шаг не закончен, остановиться и написать в чат промежуточный отчёт: что уже сделано, какие файлы записаны, что осталось, сколько новостей набрано. Потом продолжать. Следующая точка — ещё через 20 минут. Если к 22-й минуте отчёта нет — сессия зависла, редактор её прерывает и запускает шаг заново. Поэтому промежуточные файлы (`01_digest.md`, чистый файл, Word) записывать как можно раньше, чтобы после перезапуска не начинать с нуля.
- **Объём — 15–20 новостей, не больше.** Это сокращает сбор и оставляет запас на речь и Word в том же сессионном лимите.
- **Перед запуском любого агента спросить себя:** можно ли сделать это самому за 3–5 запросов? Если да — делать самому.

## Две версии текста и журнал выбора (правило редактора от 12.09.2026)

Для любого большого текста — речь, статья, авторская колонка, правки объёмом от абзаца — делаются две версии:

1. **Версия А** — черновик, написанный по правилам жанра, после редакторской перечитки (см. ниже).
2. **Версия Б** — та же версия после полного прохода по скиллу `human-writing` (аудит, переписывание, второй аудит).

**Редакторская перечитка перед версией Б (правило редактора от 12.09.2026).** Черновик не отдаётся хуманайзеру сразу. Сначала он перечитывается целиком свежим взглядом, как чужой текст: где написано криво, где неудобно читать, где фраза неестественная, где мысль спрятана в конец предложения, где повтор, где абзац можно сократить вдвое без потерь, где не хватает связки и читатель споткнётся. Всё это правится. Если текст в порядке, он не трогается: цель перечитки — сделать лучше, а не поменять ради изменений. Итог перечитки — одной строкой в чате: «перечитка: поправлено N мест» или «перечитка: без правок». Только после этого делается версия Б.

Обе записываются в папку выпуска: `<имя>_A.md` и `<имя>_B.md`. Из обеих сразу, не дожидаясь выбора, собирается Word (`Речь_<дата>_A.docx` и `Речь_<дата>_B.docx`), и оба файла кладутся в Downloads (правило редактора от 16.09.2026). После выбора собирается итоговый `Речь_<дата>.docx` из выбранной версии. В чат выводится не оба текста целиком, а список отличий: какой фрагмент как изменён и по какому признаку из скилла. Затем редактору задаётся выбор: А, Б или Б с оговорками. Выбранная версия становится основным файлом (`02_speech.md`, `Дзен_….md`), из неё собирается Word.

Каждый выбор записывается в `humanizer_log.md` в корне проекта: дата, файл, что выбрано, какие правки редактор принял, какие откатил, его замечания словами. Перед каждым новым текстом журнал перечитывается: правки, которые редактор откатывал два раза и больше, в версию Б не вносятся; правки, которые принимал, применяются без вопросов. Раз в неделю по журналу обновляется сам скилл.

Дайджест под это правило не подпадает: он проверяется скиллом сразу, без второй версии.

## Как собирать (шаг 1)

1. Прочитать `output/` за последние 2–3 дня: что уже было, чтобы не дублировать и заметить упущенное.
2. Обойти источники по кругам из `RULES.md`: сначала kremlin.ru, mid.ru, government.ru, mil.ru, ТАСС, РИА, Интерфакс, Коммерсантъ, РБК; потом дружественные и международные; потом западные. Веб-поиск по темам из раздела «Темы» + главные страницы и ленты агентств.
3. Набрать 30–40 кандидатов, отобрать 15–20, отсортировать по значимости (самое резонансное — первым).
4. К каждой новости найти: первоисточник, фото (главное изображение статьи-источника, обычно `og:image`), видео, если есть. Фото должно быть фотографией, а не карточкой с логотипом и заголовком. У РИА `og:image` вида `img.ria.ru/images/sharing/article/<id>.jpg` — карточка; настоящее фото — адрес вида `cdnn21.img.ria.ru/images/<год>/<мес>/<день>/<id>_..._1920x1080_...jpg` из тела статьи. У Интерфакса `/aspimg/<id>.jpg` размером 700×350 — карточка, 1200×675 — фото. У «Коммерсанта» `SocialPics` не скачиваются. Если настоящего фото нет — брать из статьи РИА/ТАСС о том же событии, а если и там нет — писать «Фото: нет». Видео — 1–2 ролика к каждой новости обязательно, до 4, если есть возможность и это не сильно тратит контекст (правило редактора от 16.09.2026), авторитетность ресурса не важна, главное — ролик о событии; список мест и порядок поиска — `RULES.md`, раздел 6.
5. Прогнать всё по `LEGAL.md` и чек-листу из `RULES.md` раздел 5.
6. Записать дайджест по формату из `RULES.md` раздел 6, остальное — в `rejected.md`.

## Проверка дайджеста

Галочек в дайджесте нет (решение редактора от 16.09.2026). Редактор проверяет дайджест и либо командует «убери N» / «в реджект N», либо пишет `речь`. Команда `речь` означает: в речь идут все новости, которые к этому моменту остались в `01_digest.md`. Уточняющих вопросов не задавать.

## Жёсткие требования

- Ни одного выдуманного факта, цифры, цитаты, имени. Нет источника — нет новости.
- Маркировка по `LEGAL.md` — в каждом тексте, при первом упоминании, в речи словами. Проверка делается молча; в файле нет ни «Примечаний редактора», ни списков проверенных. Итог проверки — одной строкой в чате.
- Речь и статья — чистый текст без markdown-разметки, ссылок, скобок, эмодзи: их читают вслух.
- Чужие и антироссийские позиции — с атрибуцией и пометкой «не позиция канала», по `RULES.md` раздел 2.
- Перед выдачей — чек-лист из `RULES.md` раздел 5, стоп-лист вычищен.
- Перед выдачей любого текста прогнать его по скиллу `human-writing`: аудит по списку признаков ИИ-текста, переписать совпадения, второй аудит по структуре и ритму.
- Текст пишется по-человечески, как в образцах: сплошные абзацы, без ярлыков внутри новости, без скобок с источниками, без телеграфных двоеточий, с округлёнными числами. Правила — `RULES.md`, раздел 5, «Писать по-человечески». Проверка: сказал бы так редактор коллеге вслух?
- Не выдавай текст с вопросами «уточните…» внутри: решай сам, спорное — двумя строками в чате, не в файле.
