# Новости — служба подготовки выпусков для канала в Max

Ежедневный цикл: сбор новостей → дайджест на проверку → речь ведущего → проверка → сохранение в git.
Редакционные правила — `RULES.md`. Маркировка иноагентов и запрещённых организаций — `LEGAL.md`. **Читай оба целиком перед любым шагом. Маркировка обязательна всегда, это требование редактора номер один.**
Эталоны формата — `examples/` (см. `examples/README.md`).
Как писать без признаков ИИ-текста — скилл `human-writing` (`.claude/skills/human-writing/SKILL.md`). **Загружать перед написанием любого текста: дайджеста, речи, статьи, правок.** Требование редактора от 12.09.2026.

## Структура

```
CLAUDE.md          — этот файл: как работать
RULES.md           — редакционные правила: отбор, тон, язык, форматы
LEGAL.md           — маркировка иноагентов / экстремистских / террористических / нежелательных, армия
examples/          — образцы выпусков за 04–08.09.2026
output/ГГГГ-ММ-ДД/ — рабочие файлы выпуска за день
  01_digest.md     — дайджест, не меньше 22 новостей, на проверку
  02_speech.md     — речь ведущего из одобренных новостей
  03_column.md     — статья (по команде, не каждый день)
  03_column_sources.md — источники статьи для редактора (в саму статью не входят)
  rejected.md      — что нашли и не взяли, с причинами
```

## Команды (пользователь пишет одно слово — ты делаешь весь шаг без уточняющих вопросов)

| Команда | Что делать |
|---|---|
| `новости` / `дайджест` | Шаг 1. Собрать не меньше 22 новостей, к каждой три проверенных видео, по `RULES.md` (минимум — решение редактора от 03.10.2026) (строго окно 12:00 вчера — 12:00 сегодня ± 2 ч, без догонялок за пропущенные дни: их делает другой человек, решение редактора от 25.09.2026). Записать `output/<сегодня>/01_digest.md` и `rejected.md`. Показать пользователю список заголовков с номерами. |
| `убери N, M` / `в реджект N, M` | Убрать новости из дайджеста. «Убери» — просто удалить, «в реджект» — удалить и записать в `rejected.md` с причиной, которую назвал пользователь. После этого перенумеровать оставшиеся. |
| `на проверку` | Собрать из текущего дайджеста чистый файл `output/<сегодня>/Новости_<сегодня>.md`: та же нумерация и формат, но без тегов в квадратных скобках. В Downloads md-файл не класть (решение редактора от 16.09.2026): туда идёт только Word. |
| `ворд` | Собрать Word из того, что делали последним. Дайджест: `python tools/md2docx.py output/<сегодня>/Новости_<сегодня>.md` — с фото и кликабельными ссылками (если чистого файла нет — сначала `на проверку`). Речь: `python tools/speech2docx.py output/<сегодня>/02_speech.md -o output/<сегодня>/Речь_<сегодня>.docx` (без `-o` файл получит имя `02_speech.docx`). Статья: `python tools/speech2docx.py output/<сегодня>/03_column.md -t "Статья" -o output/<сегодня>/Статья_<сегодня>.docx`. Копию Word всегда класть в `%USERPROFILE%\Downloads\`. В Downloads только docx, md-версии туда не копировать. |
| `речь` | Шаг 2. Взять все новости, которые остались в `01_digest.md` после команд «убери» / «в реджект», и собрать из них речь ведущего в `02_speech.md`, объём 1400–2400 слов (стандарт с 03.10.2026, верхняя граница поднята 05.10.2026), с конкретными цифрами из дайджеста и его источников в каждой новости (`RULES.md`, раздел 7). Галочек в дайджесте нет и вопросов «брать ли все» не задавать (решение редактора от 16.09.2026). Показать целиком. |
| `статья` | С 03.10.2026 — авторская колонка для Дзена с выраженной позицией в пользу России, живым тоном и эмоциями автора, без этнических оскорблений и без радости от страданий мирных жителей (`RULES.md`, раздел 8). Статья по самой громкой, важной или интересной новости за последнее время, обычно за неделю (или по теме, которую назвал редактор), по `RULES.md`, раздел 8 (решение редактора от 26.09.2026). Искать дополнительные факты и сверять их. Писать с полным проходом `human-writing` и отдельной вычиткой на качество повествования. Без подзаголовков, монолитным текстом; заголовок — для человека, далёкого от политики, с обозначением важности новости и статьи (решение редактора от 26.09.2026), и всегда кликбейтный, но без выдумки; ключевые слова в тексте — жирным через `**…**` (решения редактора от 28.09.2026). Видео к посту ставятся в `03_column.md` отдельными абзацами «▶ Видео: подпись — ссылка или имя файла» там, где ролик встанет в посте; в Word они выходят мелким серым шрифтом с кликабельной ссылкой и в текст поста не копируются. Записать `03_column.md` (без источников в тексте) и `03_column_sources.md`, собрать `Статья_<дата>.docx`, положить в Downloads. Показать статью целиком, источники — списком в чате. |
| `версия А` / `версия Б` / `Б, но …` | Ответ на выбор между черновиком и версией после `human-writing`. Сделать выбранную версию основной, собрать Word, записать выбор и замечания в `humanizer_log.md`. |
| `правки: ...` | Внести правки в последний созданный файл, показать только изменённые фрагменты. |
| `сохрани` | `git add -A`, коммит `Выпуск ГГГГ-ММ-ДД` (повторный — `Выпуск ГГГГ-ММ-ДД: правки`), `git push`. |

Дата — сегодняшняя по системным часам (Москва). Если папка `output/<сегодня>/` уже есть — дополняй, не затирай без просьбы.

## Бюджет сессии — правило редактора от 10.09.2026

Весь дневной цикл (новости → речь → ворд → сохрани) должен укладываться в один сессионный лимит. Лимит конечен, а токены, потраченные на незавершённую работу, пропадают. Поэтому:

- **Агенты (субагенты) — не больше двух за весь шаг, и только для сбора новостей.** Каждый агент тратит в 5–10 раз больше токенов, чем прямой поиск из основной сессии, и если лимит кончается посреди его работы, результат теряется целиком. 10.09.2026 восемь параллельных агентов сожгли весь лимит и не вернули ничего. Видео, фото, проверку по реестрам и правки делать самому, прямыми запросами WebSearch/WebFetch, без агентов.
- **Порядок в шаге 1 — сначала результат, потом украшения.** (1) Собрать новости и сразу записать `01_digest.md` с текстом, источниками и теми фото, что уже попались; в строке «Видео» временно «нет». (2) Сразу собрать чистый файл и Word (как по командам `на проверку` и `ворд`), Word положить в Downloads. (3) Только после этого искать видео (по три к каждой новости) и недостающие фото и дописывать их в файл; если роликов о событии меньше трёх, добрать смежными (тот же человек, место или тема, `RULES.md`, раздел 6), а новости, к которым не нашлось трёх роликов даже так, заменить следующими по значимости и пересобрать Word в конце. Если лимит кончится на этапе 3, у редактора всё равно есть готовый дайджест.
- **Экономить запросы.** На видео — столько запросов, сколько нужно, чтобы найти три ролика к каждой новости (решение редактора от 03.10.2026), но запросы группировать: один поиск по-русски и один по-английски на новость, все новости одной пачкой; ленты агентств читать одной страницей, а не по статье. Не перечитывать файлы, которые уже в контексте.
- **Контрольные точки каждые 20 минут (правило редактора от 10.09.2026).** В начале шага запомнить время старта. Через 20 минут работы, если шаг не закончен, остановиться и написать в чат промежуточный отчёт: что уже сделано, какие файлы записаны, что осталось, сколько новостей набрано. Потом продолжать. Следующая точка — ещё через 20 минут. Если к 22-й минуте отчёта нет — сессия зависла, редактор её прерывает и запускает шаг заново. Поэтому промежуточные файлы (`01_digest.md`, чистый файл, Word) записывать как можно раньше, чтобы после перезапуска не начинать с нуля.
- **Объём — не меньше 22 новостей** (решение редактора от 03.10.2026). Кандидатов набирать 40–50: часть отпадёт, потому что к ней не найдётся трёх роликов.
- **Перед запуском любого агента спросить себя:** можно ли сделать это самому за 3–5 запросов? Если да — делать самому.

## Две версии текста и журнал выбора (правило редактора от 12.09.2026; с 19.09.2026 отменено, см. ниже)

**Решение редактора от 19.09.2026: речь делается в одной версии А.** Версия Б и список отличий не готовятся, выбор не запрашивается. Черновик пишется по правилам жанра, проходит редакторскую перечитку и проверку по стоп-листу и скиллу `human-writing` (аудит и правки внутри одной версии), затем сразу записывается в `02_speech.md`, собирается `Речь_<дата>.docx` и кладётся в Downloads. Журнал `humanizer_log.md` больше не пополняется. Раздел ниже сохранён как история.

**Статья (решение редактора от 26.09.2026)** тоже пишется в одной версии, без выбора между А и Б, но проходит полный цикл скилла `human-writing` (перечитка, аудит, правка, второй аудит) и после него отдельную вычитку на качество повествования. На вычитку закладывается дополнительное время. Итог — одной строкой в чате.

Для любого большого текста — речь, статья, авторская колонка, правки объёмом от абзаца — делаются две версии:

1. **Версия А** — черновик, написанный по правилам жанра, после редакторской перечитки (см. ниже).
2. **Версия Б** — та же версия после полного прохода по скиллу `human-writing` (аудит, переписывание, второй аудит).

**Редакторская перечитка перед версией Б (правило редактора от 12.09.2026).** Черновик не отдаётся хуманайзеру сразу. Сначала он перечитывается целиком свежим взглядом, как чужой текст: где написано криво, где неудобно читать, где фраза неестественная, где мысль спрятана в конец предложения, где повтор, где абзац можно сократить вдвое без потерь, где не хватает связки и читатель споткнётся. Всё это правится. Если текст в порядке, он не трогается: цель перечитки — сделать лучше, а не поменять ради изменений. Итог перечитки — одной строкой в чате: «перечитка: поправлено N мест» или «перечитка: без правок». Только после этого делается версия Б.

Обе записываются в папку выпуска: `<имя>_A.md` и `<имя>_B.md`. Из обеих сразу, не дожидаясь выбора, собирается Word (`Речь_<дата>_A.docx` и `Речь_<дата>_B.docx`), и оба файла кладутся в Downloads (правило редактора от 16.09.2026). После выбора собирается итоговый `Речь_<дата>.docx` из выбранной версии. В чат выводится не оба текста целиком, а список отличий: какой фрагмент как изменён и по какому признаку из скилла. Затем редактору задаётся выбор: А, Б или Б с оговорками. Выбранная версия становится основным файлом (`02_speech.md`, `Дзен_….md`), из неё собирается Word.

Каждый выбор записывается в `humanizer_log.md` в корне проекта: дата, файл, что выбрано, какие правки редактор принял, какие откатил, его замечания словами. Перед каждым новым текстом журнал перечитывается: правки, которые редактор откатывал два раза и больше, в версию Б не вносятся; правки, которые принимал, применяются без вопросов. Раз в неделю по журналу обновляется сам скилл.

Дайджест под это правило не подпадает: он проверяется скиллом сразу, без второй версии.

## Как собирать (шаг 1)

1. Прочитать последний выпуск в `output/`, чтобы не дублировать. Упущенное за прошлые дни не добирать: выпуски идут без пропусков, за другие дни отвечает другой человек.
2. Обойти источники по кругам из `RULES.md`: сначала kremlin.ru, mid.ru, government.ru, mil.ru, ТАСС, РИА, Интерфакс, Коммерсантъ, РБК; потом дружественные и международные; потом западные. Веб-поиск по темам из раздела «Темы» + главные страницы и ленты агентств.
3. Набрать 40–50 кандидатов, отобрать не меньше 22, у которых есть по три ролика, отсортировать по значимости (самое резонансное — первым).
4. К каждой новости найти: первоисточник, фото (главное изображение статьи-источника, обычно `og:image`), три видео (до пяти). Фото должно быть фотографией, а не карточкой с логотипом и заголовком. У РИА `og:image` вида `img.ria.ru/images/sharing/article/<id>.jpg` — карточка; настоящее фото — адрес вида `cdnn21.img.ria.ru/images/<год>/<мес>/<день>/<id>_..._1920x1080_...jpg` из тела статьи. У Интерфакса `/aspimg/<id>.jpg` размером 700×350 — карточка, 1200×675 — фото. У «Коммерсанта» `SocialPics` не скачиваются. Фото обязательно к каждой новости (решение редактора от 03.10.2026): если настоящего фото у источника нет — из статьи РИА/ТАСС/Интерфакса о том же событии, затем кадр сюжета Первого канала, затем смежное фото (тот же человек, место или тема); «Фото: нет» не бывает. Видео — три разных ролика к каждой новости обязательно, до пяти, если роликов на эту тему больше (решения редактора от 03.10.2026, «супер важно»), авторитетность ресурса не важна, главное — ролик о событии; список мест и порядок поиска — `RULES.md`, раздел 6.
5. Пересчитать и проверить видео (решение редактора от 26.09.2026, после выпуска, где роликов оказалось мало). Каждый ролик открыть и убедиться, что он об этом событии и той же даты (а смежный — что на нём тот же человек, место или тема и подпись это честно говорит): у YouTube — дата загрузки, у сайтов — видео самой статьи, а не соседние ролики в плеере (у «Звезды» плеер на странице новости показывает чужие ролики, у Первого канала своё видео видно по `og:image` из `/video/material/splash/`). Цель — три ролика к каждой новости, без исключений (решение редактора от 03.10.2026). Если роликов о самом событии меньше трёх, недостающие добираются смежными: видео с кадрами того же человека, того же места или по той же теме, с честной подписью и датой (решение редактора от 03.10.2026, `RULES.md`, раздел 6). Новость заменяется следующей по значимости, только если после 4–5 запросов на двух языках не нашлось и смежных. В чат после выдачи — одна строка: «Видео: N роликов на M новостей, у всех по три» или, если замен не хватило, «меньше трёх — пп. … (сколько найдено, сколько запросов)».
6. Прогнать всё по `LEGAL.md` и чек-листу из `RULES.md` раздел 5.
7. Записать дайджест по формату из `RULES.md` раздел 6, остальное — в `rejected.md`.

## Проверка дайджеста

Галочек в дайджесте нет (решение редактора от 16.09.2026). Редактор проверяет дайджест и либо командует «убери N» / «в реджект N», либо пишет `речь`. Команда `речь` означает: в речь идут все новости, которые к этому моменту остались в `01_digest.md`. Уточняющих вопросов не задавать.

## Жёсткие требования

- Ни одного выдуманного факта, цифры, цитаты, имени. Нет источника — нет новости.
- **Фото к каждой новости дайджеста** (решение редактора от 03.10.2026), при необходимости смежное, правила — `RULES.md`, раздел 6.
- **Три проверенных видео к каждой новости дайджеста, до пяти, если роликов больше** (решения редактора от 03.10.2026, «супер важно»). Если роликов о самой новости меньше трёх, добираются смежные: тот же человек, место или тема, с честной подписью (пример редактора: новость о Кадырове, ролик с кадрами Кадырова). Правила поиска и проверки — `RULES.md`, раздел 6.
- Маркировка по `LEGAL.md` — в каждом тексте, при первом упоминании, в речи словами. Проверка делается молча; в файле нет ни «Примечаний редактора», ни списков проверенных. Итог проверки — одной строкой в чате.
- Речь и статья — чистый текст без markdown-разметки, ссылок, скобок, эмодзи: их читают вслух. Единственное исключение — ключевые слова статьи жирным через `**…**` (решение редактора от 28.09.2026, `RULES.md` раздел 8); `tools/speech2docx.py` переносит их в Word жирным.
- Чужие и антироссийские позиции — с атрибуцией и пометкой «не позиция канала», по `RULES.md` раздел 2.
- Перед выдачей — чек-лист из `RULES.md` раздел 5, стоп-лист вычищен.
- Перед выдачей любого текста прогнать его по скиллу `human-writing`: аудит по списку признаков ИИ-текста, переписать совпадения, второй аудит по структуре и ритму.
- Текст пишется по-человечески, как в образцах: сплошные абзацы, без ярлыков внутри новости, без скобок с источниками, без телеграфных двоеточий, с округлёнными числами. Правила — `RULES.md`, раздел 5, «Писать по-человечески». Проверка: сказал бы так редактор коллеге вслух?
- Не выдавай текст с вопросами «уточните…» внутри: решай сам, спорное — двумя строками в чате, не в файле.
